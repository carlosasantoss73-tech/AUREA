**Status at 2026-10-10:** PR #199 is merged into `main` at `41cccaa57a3369d7bad89185cc6fc5c6d3ec7bed`. The Worker is **not deployed** and the pilot is **not operational**. Do not call the pilot operational until the end-to-end gates below pass.

## A. Deploy the intake shell safely

1. PR #199 is already merged. Post-merge evidence checked: AUREA Cloud Continuity, Windows Migration Audit, and the AUREA P0 check passed; the ECP Worker Build is a dry-run only and does not deploy.
2. First create and verify the Cloudflare Access application and policy for the intended pilot user. Obtain its team domain and AUD. The deployment workflow now refuses to deploy unless both values are supplied; this prevents an unprotected bootstrap deployment. Required repository secrets:
   - `CLOUDFLARE_API_TOKEN` — least-privilege token for Worker deployment and secret updates.
   - `CLOUDFLARE_ACCOUNT_ID`.
   Optional secrets:
   - `ANTHROPIC_API_KEY` — provider calls remain blocked if absent.
   - `ECP_GOOGLE_DRIVE_ACCESS_TOKEN` — institutional retrieval remains blocked if absent or read-only.
3. In GitHub Actions, run **ECP Cloudflare Pilot Deploy** with `confirm_deploy=true`, the verified Access team domain and AUD, and (if available) the verified institutional index file ID. A blank index ID keeps institutional analysis blocked; it does not bypass the context gate.
4. In Cloudflare Workers, verify **Protect this Worker behind Access** for `aurea-ecp-pilot` before sharing the URL. Cloudflare documents Worker-level Access as protecting the Worker's associated domains, including its `workers.dev` hostname: https://developers.cloudflare.com/workers/configuration/cloudflare-access/
5. Confirm the Access policy and test that an unauthenticated request cannot access protected endpoints. The deployment workflow inputs are:
   - `access_team_domain`: team name only, without `.cloudflareaccess.com`;
   - `access_audience`: the AUD tag generated by the Access application;
   - `institutional_index_file_id`: the verified ID of the current institutional index, not an inferred ID;
   - `anthropic_model`: a model ID confirmed active for the account.
6. Verify `/health`. It must distinguish runtime readiness from institutional-context and analysis readiness. Do not expose the URL to customers while Access or identity configuration is incomplete.

## C. Real-expediente pilot acceptance

- Load originals in batches below the interface limit. Currently supported: PDF with selectable text and XLSX. Scanned-PDF OCR and legacy XLS are not supported by this pilot.
- Verify original document IDs, SHA-256 versions, page/sheet-row localizers, extraction warnings, and complete coverage.
- Use the explicit **Ejecutar análisis trazable** action. The request must pass the institutional Context Retrieval Gate, Runtime Admission, permission gate, and registered provider adapter.
- If institutional context is missing, the provider must not be called and the result must remain BLOCKED.
- Validate citations and localizers against the original files, compare the same requirements across all offerors, preserve NO CONCLUYENTE when evidence is insufficient, and have a human reviewer check the report.
- Run a negative test (missing context or unreadable document) and confirm fail-closed behavior.
- Only after these checks may the pilot be marked OPERATIVO. This pilot does not recommend an awardee.
